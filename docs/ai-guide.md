# AI 辅助定制与排错提示词

如果你想用 Codex、Claude Code、Cursor 等 Agent 工具，或者用网页版 ChatGPT / Claude / Gemini 来定制自己的固件和界面，千万不要只说一句“帮我写个能刷进 Rainy75 的固件”——AI 会瞎编内存地址。把本仓库对应文件提供给它，再套用下面的提示词，改出来的代码才能直接编、安全刷。

> 本项目只保留**基础屏幕版**（大单键、时钟、电量、连接图标、原创机器人）。歌词播放器扩展已移除，提示词里不要要求 AI 恢复字库、歌词协议或 Windows 后台。

## 定制固件需要把什么传给 AI？

**先说最重要的一条：虽然仓库 `vendor/` 里放了 [Rainy75V2烧录工具20261112-1beta1.html](../vendor/Rainy75V2烧录工具20261112-1beta1.html)，但定制固件时千万不要把它、`inputs/*.bin` 或 `libISP585.a` 上传给聊天 AI。**

原因很实际：这份烧录 HTML 约 **1.14 MB**，其中绝大部分体积是 `FIRMWARE` 对象里用 Base64 + 异或混淆编码后的**三份原厂二进制固件机器码**（键盘 `0x3F`、接收器 `0x26`、屏幕 `0x0002`）。AI 读不懂编码后的机器码，不仅帮不上忙，塞进对话还会撑爆上下文、误导它去改烧录网页本身，而且这些二进制归 WOB 原厂所有（非 MIT 开源）。

AI 真正需要看的是**本仓库的纯文本源码、配置和文档**：

### 情况一：用本地 AI 编程工具（推荐：Cursor / Claude Code / Codex）

- 直接把本仓库克隆到本地，用 AI 工具打开项目目录；提醒它**不要读取 `vendor/*.html` 里的大段编码固件**，只改 `profiles/`、`firmware/`、`web/`、`studio/`、`tools/`。
- 想让它顺便编出可刷入的 `.bin`：确保 `inputs/` 里的三个文件在位、`llvm/bin/` 里有 `clang.exe` 与 `ld.lld.exe`，AI 直接调用 `tools/build.py` 即可。

### 情况二：用网页版聊天 AI（ChatGPT / Claude / Gemini 等上传文件对话）

- **打包上传时剔除 `vendor/`、`inputs/`、`build/`、`llvm/`**：只把纯源码打成压缩包（几百 KB）再传，否则附件体积和上下文会被二进制占满。
- 如果平台限制附件数量，按你想改的内容挑文件：

| 你想让 AI 帮你改什么 | 必须传给 AI 的仓库文件 | 你还需要额外提供的材料 | 拿到 AI 结果后怎么做 |
| --- | --- | --- | --- |
| **只改配色 / 改大按键图标** | `profiles/themes.json`、`profiles/keys.json`、`profiles/font.json`、`tools/assets.py`、`docs/customization.md` | 想要的配色风格或参考图、想增改的按键 | 把改好的 `.json` 放回本地，跑 `build.py` 编译后刷机 |
| **换成自己的 GIF 角色动画** | `profiles/themes.json`、`tools/assets.py`、`docs/customization.md` | 你自己的图片 / GIF 源文件 | 让 AI 裁成 `320×172` 并满足全帧覆盖与 `(22,39)` 标记像素，再上传到 S1 |
| **改画面排版 / 新增状态** | 上面全部 + `README.md`、`AGENTS.md`、`firmware/ips/*`、`firmware/main/*`、`tools/build.py`、`docs/protocol.md`、`docs/compatibility.md` | 你想要的布局草图、数据来源说明 | 替换本地源码后运行 `build.py` 和测试，确认无报错再烧录 |

> 发提示词时还要交代清楚三件事：① 你改的是**基础屏幕版**，不要引入字库、歌词固件或 Windows 后台；② **不要让 AI 把你的原厂 `.bin`、个人设备号、本地路径或私人图片写进可公开提交的内容**；③ 网页版 AI 改完代码无法替你实机验证，务必先自己跑一遍 `unittest` / `npm test` 和 `build.py` 的边界检查再刷。

```text
具体现象：【例如时间显示 --:--:--、校时报状态 7、连接图标不更新、大按键图标错位】。

要求：
1. 用 web/diagnose.html 的只读查询路径解释每个读数字段的含义，说明是固件问题、素材问题还是操作顺序问题；
2. 不要通过删除 SHA-256 校验、地址边界断言或跳过预检来“让流程通过”；
3. 给出最小的可复现步骤和你希望我提供的读数，区分“代码编过”“模型跑通”和“实机确认”。
```

## 怎么判断 AI 改得靠不靠谱？

硬件相关的改动最怕 AI“看着顺眼其实瞎编”。让它干完活后，重点盯三件事：

1. **有没有拿出实打实的文件路径、构建边界检查和单测结果**（而不是笼统说“理论上同型号芯片都能用”）；
2. **有没有分清“代码编过”、“模拟器跑通”和“真键盘上亮了”这几层概念**；
3. **遇到未知项时有没有老实说不知道**，而不是靠删掉 `build.py` 里的校验或者硬凑地址来骗自己“编译成功”。
