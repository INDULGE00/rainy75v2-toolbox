# 通信协议与内存边界参考

这篇文档汇总了本项目逆向与自定扩展的底层协议格式和 Flash/SRAM 边界，方便开发者排查问题或继续魔改。这些属于社区自定兼容实现，并非 WOB 官方公开 API。

所有 PC 端配置、传图与校时均通过键盘 USB 本体完成：
- **USB 设备**：`VID 0x36B0 : PID 0x3075`
- **HID 接口**：`Usage Page 0xFF60`，`Usage 0x61`，`Report ID 0`，固定 `256` 字节报文（公开工具尚未实现接收器写屏）

---

## 1. 主控 / 屏幕通用控制报文（`BE 1A` / `BE E4`）

### 下行控制指令

```text
BE 1A LEN 0D OP ID_LO ID_HI 00 [PAYLOAD...] SUM_LO SUM_HI ED
```

- `LEN = 11 + payload长度`（整体不足 256 字节时在末尾补 `0` 发送）
- `SUM16`：从下标 `3`（即 `0D`）到 `PAYLOAD` 最后一个字节的累加和（16 位小端，低字节在前）

### 读应答描述符（E4）

```text
请求：BE E4 0A 84 04 00 00 34 02 ED
响应：BE E4 0E 84 04 00 00 SUB STATUS VALUE_LO VALUE_HI SUM_LO SUM_HI ED
```

正常响应的 `SUM16` 覆盖下标 `0..10`。部分原厂旧分支会返回固定校验和 `0x0357`，`parseAck` 做了兼容标记（仅用于适配旧回复格式，不代表对数据完整性的加密校验）。

### 自定义扩展 OP 一览

| 目标与 OP | 说明 |
| --- | --- |
| **主控 `OP 15 / ID 9`** | 查询能力值：`V7.1` 返回 `0x4350`（其他字段查询应答状态码为 `0xD0 + ID`） |
| **主控 `OP 18`（8B payload）** | `secondsOfDay:u32LE` + `rate:u32LE`。主控收到后立刻读取当前 RTC 寄存器，把校时锚点持久化到 `0x49000` 页并向屏幕推送时间 |
| **主控 `OP 15 / ID 10..23`** | 只读调试查询：`10/11` guard 低/高、`12/13` 参考 cycles、`14` 参考 day、`15` guard 有效标志、`16/17` magic、`18/19` 参考秒数、`20/21` rate、`22/23` checksum |
| **IPS `OP 11 / ID 0`** | 查询能力值：`L6` 返回 `0x5536`（其他字段查询应答状态码为 `0xB0 + ID`） |
| **IPS `OP 11 / ID 1, 2, 3`** | 分别读取：最近键码、电量/充电原始值、连接模式原始值 |
| **IPS `OP 11 / ID 4, 5, 6`** | 分别读取：时钟源状态（`0x401` 无效 / `0x402` 已同步）、BCD 时分秒低 16 位 / 高 16 位 |
| **IPS `OP 11 / ID 14, 15`** | 只读芯片硬件信息：`ID 14` 为片内 Flash 容量 `F_SIZE`（KiB），`ID 15` 为系列字节（`0x0D` = 13） |
| **IPS `OP 11 / ID 16`** | 大写锁定状态：`1` = 大写（实心灯 + `A`）、`0` = 小写（空心灯 + `a`），由屏内按 CapsLock（usage `57`）自行计数 |
| **IPS `OP 2 / OP 5`** | 暂停屏幕合成（文件上传前准备）/ 恢复屏幕合成 |

通用状态码约定：`1` = 成功、`2` = 忙、`3` = 格式错误、`5` = 参数越界、`7` = 写入或校验失败。

## 2. 主控 ↔ 屏幕内部串口事件

- **按键通知**：`BE 15 08 KEY_LO KEY_HI RAW5 RAW6 ED`。在当前匹配版本里，`RAW6` 是一个 Shift 布尔标志（bit0），**不能按标准 HID 修饰键位掩码去解析**。
  ⚠ 主控不转发大写锁定状态，屏幕只能自己数：每次收到 usage `57`（CapsLock）就翻转一次本地标志，
  所以上电后第一次按 CapsLock 之前显示的是「空心灯 + a」的默认状态。

- **状态通知**：`BE 19 07 BATTERY CHARGE MODE ED`。当前映射为 `USB=1`、`2.4G=0`、蓝牙槽位 `2..4`。
- **屏幕请求时间**：`BE 1D 04 ED`。
- **主控回复时间**：`BE 1A 08 0D (0x80 | HOUR) MIN SEC ED`；时间无效时回复 `BE 1A 08 0D 9F 00 00 ED`。

**拉取与插值策略**：屏幕刚开机或当前时间无效时每 `1` 秒请求一次快照；已经同步后每 `30` 秒请求一次校准，期间靠屏幕本地毫秒计时插值走秒；如果超过 `90` 秒一直没收到有效快照，屏幕会把时间置为无效（`--:--:--`）。串口总线忙时直接跳过本次推送等下一轮，不做死等阻塞。

## 3. 素材上传协议（`1A` 子命令）

复用原厂文件传输子命令：`BEGIN=1`、`DATA=2`、`END=3`、`ABORT=4`：

- **S1 动画上传**：11 字节固定文件名 `S1      GIF`，后接文件长度 `u32LE` 和整体 `CRC16-CCITT`（初值 `0xFFFF`，多项式 `0x1021`，无最终异或）。每个 `DATA` 包带 `u16LE` 递增包号，常规载荷 `232` 字节。
- 常见失败：`BEGIN` 返回状态 `4` 表示屏幕外置 Flash 剩余空间放不下这个动画，把定制台的「动画体积上限」调小重新生成；连续返回 `255` 表示屏幕不接受这次上传（文件名残留或上一次写入未收尾），先写一个 454 B 占位素材释放槽位再重传。

## 4. 显示与素材约束

- 屏幕在 `320×172` 帧上循环播放 S1 缓存的 GIF，补丁代码在每帧合成时把时钟、电量、连接图标与大单键叠画到固定区域，因此**主题配色必须与上传的 S1 GIF 配对**。
- 屏幕原厂解码器要求每帧完整覆盖（`disposal=1`），公开机器人每帧恢复完整 `320×172`，像素 `(22,39)` 的 RGB565 颜色必须不同于主题背景；自定义动画必须满足此条件，构建器与素材测试会校验。
- 不往桌面端添加键盘钩子：按键、电量与连接方式都来自主控原生通知。
- 顶部状态栏从左到右：时钟、大写锁定灯（`ui_geo[5]`，实心 + `A` / 空心 + `a`）、连接方式图标、电池、百分比。

## 5. IAP 烧录协议与 Flash 布局

### IAP 报文（64B，Report ID 0）

目标设备：主控 `0x3079`（APP 起点 `0x2000`），屏幕 `0x3078`（APP 起点 `0x4000`）。

- `ERASE`：`81 00 address:u32LE`（擦除成功前两字节返回 `00 00`）
- `PROGRAM`：`80 N data...`（每次最多 `62` 字节）；写完后发 `80 00` 刷新收尾
- `VERIFY`：`82 N address:u32LE data...`（每次 `56` 字节；如果总长度末尾不足 56B，向前回退重叠校验最后 56B，保证覆盖每一个字节）
- `END`：`83 00`（结束重启，不强制要求应答）

### 代码与数据区边界

- **基础版 IPS**：代码区 `0x0807EC90..0x08080000`，模块 RAM `0x2005F000..0x20060000`，镜像大小 `507904` 字节。
- **键盘主控（CH585）**：代码接在原厂 APP 之后且不得越过 `0x49000`；`0x49000..0x49FFF` 为专用校时数据页，结构依次为 `magic (0x434C4B31)`、`cycles`、`seconds`、`rate`、`day`、`XOR check`（各 `u32`），后跟 `guard`。校时写入顺序是：擦除该页 → 写后 24 字节（包含 `guard = 0xFFFFFFFF`）→ **最后才写 4 字节 `magic`** → 读回核对，防止写入中途断电留下半截脏数据；检测到 RTC 计数回退时通过把 `guard` 写为 `0` 立即作废旧锚点。
